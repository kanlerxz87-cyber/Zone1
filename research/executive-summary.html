Findings that matter

  1. Blocking: the three links are not monetised as supplied — no tracking tag on any of them.
  2. Structural: this is a one-category, two-brand programme. Concentration risk is the dominant commercial risk.
  3. Data reality: Amazon's public data surface is far smaller than the brief assumes. Prices, ratings, review counts, BSR and category commission rate all require authentication or API access this account does not have.
  4. Compliance is the easy part and it is done: disclosure placement, trademark attribution, no fabricated experience, no price claims — all enforced by the build, not by memory.
  5. Content is ready: three articles are publishable today because they only claim what a manufacturer's spec sheet supports.

Verification method, in one paragraph

Every value on this site lives in data/*.json as {value, source, verified}. The site is generated from that data, and a build check fails if any published row lacks a source URL, if a field marked verified has no source, or if any internal link is broken. Anything that could not be confirmed is stored as null and renders as an explicit "unverified" blank with a link to its entry on the Flagged for Review page. Analysis is stored in a separate file and labelled derived wherever it is displayed.
