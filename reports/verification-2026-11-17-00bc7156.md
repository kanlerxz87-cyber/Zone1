## 3. The control test, and the caution it weakens

Twelve passes of flags explain "identity unconfirmed" partly by pointing at destinations served with
`plpRedirect=mhFallback` — as if a fallback page proved the short link missed its target.

**Test run 2026-11-17:** request the bare, known-correct URL `https://www.amazon.com/dp/B0CDY277D3`. No short
link, no redirect chain, an ASIN this repository already carries.

**Result:** served at `https://www.amazon.com/dp/B0CDY277D3?lv=shuf&channelId=500&plpRedirect=mhFallback`,
with the register's recorded title.

**Conclusion:** the marker is a property of how Amazon serves detail pages to this fetcher. It is not
evidence about a submitted link. The **caveat is correct** — the **reason attached to it is not**, and a wrong
reason propagates: it has now been copied through a dozen registers, a handover sheet and a landing-page
callout. What actually keeps identity open is independent and survives untouched: a nine-character token
names no ASIN, and nobody with an account has ever stated what the links were for.

Deliberately **not** fixed in this pass: the four rows are not reworded on a single observation by a single
agent. That is `SG-38`, with `Q-29` asking the next reader to repeat the sixty-second control first.

## 4b. Two conventions main had already adopted, adopted here too

* **Reader links.** #132 set the policy that this site sends readers to the tagged `/dp/<ASIN>?tag=…`
  listing rather than through the supplied `link.amazon` short links. The cluster page follows it: each card
  carries one tagged, `rel="sponsored"` button, and the submitted token is printed as `<code>` evidence with
  its source badges. One nuance recorded rather than swallowed: #132's stated reason is that a tag "cannot
  travel" through a `link.amazon` redirect, which is plausible from §2(b)'s wording but is not a fact
  anyone here tested. The cluster does not depend on the answer either way — the tagged listing is the better
  path regardless — but the register should not adopt an untested mechanism as established. If someone wants
  it settled, it is a two-minute test of `link.amazon/<token>?tag=<id>` in a browser, and it belongs on
  `measurement.html`'s open list rather than in prose.
* **Orphan data.** The rule this repository enforces hardest — appended data must be reachable from a
  generated page or the build fails — was turned on this pass's own record: the control test is rendered as a
  table on `product-intent.html`, where the redirect observations live, with each row citing the source ids
  or the raw fetch log that produced it.

## 6. What this pass could not do, and why that is on the page

Six rows are blank. Four of them (model code, waterproof rating, warranty, temperature ranges) need blocks
that sit **below the first chunk of a page**, and in this sandbox a request for a later chunk fails with an
upstream proxy signing error — so the fetch physically stopped short. Figures were available in search
snippets of those same pages; none was used, because a snippet is not a read. That limitation is printed in
§"What this page could not reach" on the cluster page, in `read_constraints` in the dataset, and as `SG-39`
("a browser, not a build").

Nothing was claimed about conversions, revenue, trending status or demand. No analytics endpoint was
invented: GitHub Pages serves static files, and a counter with no endpoint behind it produces invented
numbers — the position `arena/5b17c077-zone1` documents in its measurement spec, which this pass does not
duplicate.
