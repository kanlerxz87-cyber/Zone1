## 2. Method, and why the method is what it is

This sandbox has no direct outbound network: a plain `urllib` request to
`affiliate-program.amazon.com` fails with `TLS/SSL connection has been closed (EOF)`. Every live
read in this pass therefore went through the environment's server-side fetch, which returns the
page's own text. That has two consequences that matter for reading this record:

* A source that the fetch could not render is reported as **not re-read**, never as "unchanged".
  Silence is not agreement.
* Where a live page and a published value disagreed, the *published value* is what would have
  changed — and in this pass nothing needed to change. That is stated as a fact, with the string
  that was read back, so a later pass can check it rather than trust it.

## 5. The published-site audit (W3) — and the three defects it found

The repository's gates read the **dataset** and the **generator**. Nothing read the **page that
ships**. `scripts/audit_pages.py` (new, in this pass) reads the rendered HTML of every page the
root generator writes and checks:

* per-row source coverage across every data table (a row that asserts a value must link the
  official document that states it; a row that links only to this repository or to the Flagged
  page is reported, because that is the documented pattern for a design opinion or an unconfirmed
  value, and it is never silently passed);
* duplicate `id`s; JSON-LD that parses; canonical URL present and equal to the published URL;
  meta description; exactly one `<h1>`; no skipped heading level; no `<h5>`/`<h6>`;
* `<img>` without alternative text; `<html lang>`; the mobile viewport;
* data tables without a header row; every product page carrying its `link.amazon` anchor;
* the house banned-phrase list re-checked against the HTML — where a phrase is **quoted** (the
  site quotes the phrases it bans, and quotes brand copy verbatim as evidence) it is not slop, and
  the audit says so rather than reporting it.

**First run: 50 errors.** After triage, three defect classes were real:

| # | Defect | Where | Severity | Fix |
|---|---|---|---|---|
| **D1** | The footer labelled its five columns with `<h5>`, so **every** generated page skipped a heading level (h2/h3 → h5). The outline a screen reader builds from the page was broken on 33 pages, and the defect is invisible in a visual review | 33 pages | Medium — accessibility and document structure | Footer headings are now `<h2>` (a `<footer>` is its own sectioning root, so h2 is the correct level there); the CSS that gives them their small-caps look was moved with them |
| **D2** | `handover.html` went `h1` → `h3`: the five owner actions were labelled a level too deep | 1 page | Low–medium | The five action titles are now `<h2>`; the rule that styles them was moved with them |
| **D3** | `404.html` went `h1` → `h3` for its two card headings | 1 page | Low | Now `<h2>`, with the card's compact size kept |

Two things the audit reported that were **not** defects, and were not "fixed":

* *"404.html: no canonical link"* — **correct as it is.** The repository's own
  `check_seo_metadata()` guard requires the 404 page to be `noindex` and forbids it from
  declaring a canonical URL. The audit was corrected to match that rule rather than the other way
  round.
* *nine rows that cite the repository rather than an official source* — **the documented
  pattern.** They are the site's own legend table, the two internal KPIs (flag F26 says outright
  that they are operating targets, not facts about Amazon), the four design-opinion suggestion
  rows on the parallel marketing-directions page (whose own callout says "Where the row is a
  design opinion, it says so and points to Flagged for review"), and one open question whose
  answer is genuinely not yet known. These are reported as warnings, every time, so that "the row
  cites the repository" can never be mistaken for "the row cites the source".

**After the fixes: 0 errors, 9 warnings** — and the nine warnings are the nine rows described
above.

### The defect class is now impossible to reintroduce silently

`build.py` gained `check_heading_order()`: one `<h1>` per page, no heading more than one level
deeper than the one before it, no `<h5>` or `<h6>` anywhere. It was **proved to fire**: with an
`<h5>` injected into the footer, `python3 build.py` exited **1** and named the page and the
heading; with the file restored byte for byte it exited **0**.

`scripts/audit_pages.py` was added to `scripts/ci-check.sh`, so the full page audit now runs in
CI rather than being a one-off finding.
