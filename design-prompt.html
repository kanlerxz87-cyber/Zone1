Design prompt pack: review before anything changes

The design and content-production suggestion layer: a paste-ready design prompt, ten design suggestions with live status, the article topic queue, organic-traffic tactics, editorial voice rules and a decision register. Every row is a suggestion for you to approve, reject or modify — the status column records which of them the repository already satisfies today.

How this page fits the other registers.

Suggestions is the governance queue (SG-01…): what to decide and what it costs. Questions is what is not known yet (Q-01…). Decisions & handover settles strategy — which niche, which channels, what to measure. Content and traffic plan is the proposal view of the article queue — intent, angle and citations per topic. This page is the design and content-production layer: how the site should look and read, whether each proposed article has shipped yet, and the tactics that turn the strategy into published pages. Product facts are not here — they live in the full dataset, each with its official source.

The design prompt

Paste the block below into any designer or AI assistant used to restyle the site. It describes the site exactly as it is today, names the components and rules that must survive a redesign, and ends with the acceptance criteria every change has to pass. Nothing in it asks for a claim the site cannot source.

ZONE1 KITCHEN — DESIGN PROMPT (paste-ready)
Goal: polish this Amazon affiliate site so it reads like a human-run marketing publication — not an AI-generated data dump — without weakening its verification discipline.

SITE AS IT IS TODAY (do not contradict these facts)
- Static site generated by build.py from data/*.json; live at https://kanlerxz87-cyber.github.io/Zone1/
- Three tracked air fryers (Chefman 6 Qt dual-basket, Emeril 26 QT French-door oven, Chefman 8 Qt single-basket). The supplied Amazon short links resolve to candidate ASINs whose product identity is UNCONFIRMED and must stay labelled as such.
- Every published number carries a source badge (S1-S31) linking to the official page it came from. Values that cannot be confirmed are left blank and listed on the Flagged-for-review page — never guessed, never back-filled.
- Amazon prices, star ratings and review counts are NEVER displayed (Amazon Program Policies 2(b) and 6(t)). Manufacturer list prices are allowed when cited to the brand's own page.
- No hands-on testing is ever claimed; no superlative ("best", "top-rated") is asserted as fact; vendor statements are labelled as brand claims.
- An affiliate disclosure bar sits above the header on every page: "As an Amazon Associate I earn from qualifying purchases."

DESIGN DIRECTION
1. Keep the dashboard skeleton — sticky sidebar, top bar, disclosure band, stat tiles, sourced tables — and keep the landing page editorial: one-sentence value proposition above the fold, then a format finder, then sourced article cards.
2. Palette (shipped pass 12, 2026-11-16 — reuse these tokens, do not invent new colors): warm paper #f5f1e8, cream cards #fffdf7, aged-paper #efe9d8, ink #212821, brand deep green #245746 (deep #16382e), terracotta accent #b05a2f, hairlines #e4ddc9; ok/warn/bad/info tints are CSS variables. All 23 foreground/background pairs were measured at >= 4.5:1 (WCAG AA) during the pass-12 audit.
3. Typography: serif display via --serif (Iowan Old Style / Palatino / Georgia stack) for headings and hero, system sans for UI and body; sentence case; tight letter-spacing on display sizes. Source badges (.src) render as quiet footnote-style chips, never as buttons, so prose stays readable.
4. Components that must survive any redesign: source badge (S#), blank cell with "not confirmed" pill, flag pill, stat tile, callout variants (info/warn/bad), comparison table with per-cell source links, disclosure bar.
5. Shipped structure (pass 12, 2026-11-16 — keep on any future redesign): topbar with compact primary nav (Picks / Buying guide / Articles / Compare) plus verified-data stamp; sidebar grouped Shop smart / Products / Trust & evidence / Owner workspace; deep-green footer; decorative artwork is stroke-only inline SVG (three format glyphs) — no photography, per D-5.
6. Mobile-first: single column below 820px, tap targets at least 40px, no horizontal scroll, prefers-reduced-motion respected, focus-visible outlines kept.
7. Page inventory to keep: Home, This week's picks, Buying guide, Articles, Category, three product pages, Comparison, Full dataset, Compliance, Flagged, Suggestions, Questions, Decisions & handover, Executive summary, Re-verification, Platform, Previous passes, Design prompt pack.

EDITORIAL VOICE (anti-AI-slop rules - non-negotiable)
- No unverified superlatives: never "best", "top-rated", "revolutionary", "must-have", "game-changing". If it is not sourced, do not say it.
- Specific numbers beat intensifiers. Contractions and questions are welcome. Mix short and long sentences.
- Show the gaps: blank cells, published conflicts and "unconfirmed" badges are content, not bugs.
- Label every manufacturer statement as a brand claim, not a tested fact.
- Never write "we tested", "our pick", "in our kitchen". The site does not test products.
- One topic per page; every page stamps when its sources were read.
- Banned openers and claim guards are enforced in build.py (see decisions.html, anti-slop list).

SEO LAYER (already implemented - keep it)
- Every page carries canonical URL, og:* tags, twitter:card, meta description and JSON-LD (WebSite / Article / BreadcrumbList); robots.txt and sitemap.xml are regenerated by build.py; a build guard (check_seo_metadata) fails the build if any of it is dropped. Social card: assets/og-card.png.

ACCEPTANCE CRITERIA (all must pass before any change merges)
1. python3 build.py — all build guards green: every table row sourced, disclosure present, SEO metadata present, affiliate links qualified rel=sponsored, no price/rating leakage, unique flag IDs.
2. python3 verify.py — 0 errors.
3. bash scripts/ci-check.sh — unit tests, data audit, link check all green.
4. Every table row still links to an official source; every unverified value still blank and flagged.
5. The disclosure bar and the no-testing/no-superlative rules are unchanged.
