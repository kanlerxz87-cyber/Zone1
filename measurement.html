What this site counts, and what it refuses to count

A shop that cannot see which shelf people walk past is guessing. This page is the instrument panel: five defined events, recorded on your own device, sent nowhere — and the two numbers that only Amazon's own reports are allowed to produce.

The measurement layer, split into the part that can be built on a static host and the part that cannot. The counter is built. The endpoint is not, because there is no server here to host one, and pretending otherwise would mean either shipping a form that posts to nothing or inviting a third-party script onto a site whose footer currently states that it runs no analytics. Both of those are worse than an honest gap, so the gap is named and the shape of the endpoint is specified instead.

The five events

The brief names 'the five defined events' without defining them, and no earlier register in this repository enumerates a set of five. The set below is therefore this pass's proposal, written against the two questions the site can actually answer with data it is allowed to hold. It is a register entry, not a claim that the owner asked for these five.

Rendered from the one place those numbers exist: this browser. No row here was sent anywhere, and no other visitor's counts can appear on it.

Reading the local ledger…

Campaign ledger — 0 rows

Every field in this ledger describes something that only exists inside an Amazon Associates account or a webmaster tool. Nothing in this repository has read either. A row typed here by an agent pass would be a fabricated number wearing a provenance costume, which is the failure this whole project has spent thirteen passes trying not to have.

Derivation rules

  • Conversion rate is not stored. It is clicks over sessions or orders over clicks, and which one is defensible depends on the report's own definitions; if the site ever shows one it will be computed at build time from the two stored columns and labelled with its denominator.
  • Revenue is not stored and no forecast is computed here. The published commission table gives rates by category, and no row in this register establishes which category Amazon assigned to a given ASIN (Q-11 stays open).
  • A row is never edited. If a number is corrected, the correction is a new row with its own obtained_on, and the superseded row keeps a pointer to it.

Where the first rows will come from

  • Associates Central > Reports, once the account passes review (Q-03) and one tagged link has been live long enough to register.
  • Search Console query data, once the site is verified (SG-29), which is also what chooses the next topic instead of a hunch.

check_campaign_ledger() in build.py fails the build if any row lacks source, obtained_on or period_start, or if a row cites a source host that is not in data/sources.json. The gate is the point of the file: without it, the ledger is a place to put a number you liked.

The endpoint that is not switched on

A self-hosted endpoint needs a server that receives, stores and can be shown to delete data. GitHub Pages serves static files. There is no place in this repository to put that server, and pointing the client at somebody else's collector would be the third-party analytics the site currently and truthfully says it does not run.

Required before it can be enabled

  • An owner decision to host something, and where the data lives (Q-08).
  • A rewrite of the footer's no-analytics statement and the privacy page in the same commit that turns collection on, against Program Policies 3(e).
  • A retention and deletion answer. Without a server that can delete, an endpoint is an accumulation point.
  • A decision on whether readers must be told: consent requirements depend on the visitors' country, which this repository has never had a verified statement for (Q-20).

Set data/config.json -> analytics_endpoint to the absolute URL and set data/measurement.json -> endpoint_contract.status to 'enabled'. The client stays off while the URL is empty, so a half-configured state is impossible by construction.

The only report that pays

Clicks and orders that pay are counted by Amazon, not by this site. The Associates reports are the only authorised source for the numbers in campaign-ledger.json, and this repository's rule is that a row enters that ledger only with a dated provenance line naming the report it came from. S2 S3 S6

What none of this can tell you

  • How many people clicked. Everyone's counter lives on their own device; there is no aggregate of EVT-1 across visitors until an endpoint exists. That is the honest limit of a static host, and it is why the aggregate plan routes through Associates Central instead.
  • Whether a click became a sale. Order attribution belongs to Amazon's report; the site never sees it.
  • Anything about a person. By construction, not by policy.
  • Whether the site ranks. Search performance comes from Search Console, which is SG-29 and an owner action.

Cookies & privacy

This site sets no cookies itself, runs no analytics, and has no comment forms or accounts. Following an Amazon link takes you to Amazon, whose own privacy notice and cookie practices apply from that point. No data you enter here is collected, because there is nowhere to enter it.

Amazon's Program Policies §3(e) require an accurate statement of cookie and third-party technology use on Associate sites. This notice satisfies that requirement for the current build; it must be updated the moment any analytics, embeds or affiliate-network script is added.
