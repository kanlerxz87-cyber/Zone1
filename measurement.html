Measurement: five events, defined and not yet sending

The brief asks for click and conversion measurement. This page is the specification for exactly what would be recorded and what is deliberately excluded — and the honest reason none of it is running. No count, rate or revenue figure appears on this page, because none has been measured. An empty ledger is a true statement; a filled one here would not be.

Status: defined not shipped

Four of the five events need a server endpoint this repository does not have. The fifth, reported orders, can only be entered by hand from the owner's Associates report. Neither is something a session can invent.

Why nothing is sending yet

  • The site is static files on GitHub Pages. There is no server to receive a beacon, so a 'self-hosted analytics endpoint' cannot be built inside this repository — it needs a host the owner controls.
  • The footer states, truthfully today, that the site sets no cookies and runs no analytics. Program Policies §3(e) requires an accurate statement of cookie and third-party technology use, so the moment a beacon ships that sentence is false unless it is updated in the same commit.
  • A click counter that reported a number without a real endpoint behind it would be an invented number on a page that promises every value is sourced. Nothing here reports a count it did not measure.
  • Amazon's own conversion reporting lives in Associates Central and is not available to a third-party static site, so reported orders must come from the owner's first-party report, not from this site.

The five events

EV-01 · page_view

Fires when: A human opens any article, product, comparison or guide page.

Records

  • page slug
  • UTC date
  • whether the arrival carried a utm_source/campaign parameter

Never records

  • IP address
  • user agent
  • referrer URL
  • reader identifier

Slug and date only. A per-reader identifier would turn this into behavioural tracking and break the no-cookie statement.

EV-02 · outbound_product_click

Fires when: A reader clicks any link whose href points at www.amazon.com/dp/<ASIN>.

Records

  • ASIN
  • page slug the click came from
  • UTC date
  • the Associates tag present on the link

Never records

  • order value
  • what the reader bought
  • any Amazon session data

This is the earliest point at which this site can observe intent without Amazon's data. It counts interest, not revenue, and must never be labelled a conversion.

EV-03 · guide_completed

Fires when: A reader scrolls a sourced article to its final section, measured at the last heading, not at the footer.

Records

  • page slug
  • UTC date

Never records

  • time on page
  • scroll depth histogram
  • reader identifier

A single completion flag is enough to answer 'did anyone read this'. A depth histogram costs a cookie-free session id and buys nothing the editorial calendar uses.

EV-04 · comparison_table_viewed

Fires when: The comparison table becomes visible in the viewport on compare.html or a product page.

Records

  • page slug
  • UTC date

Never records

  • which rows were expanded
  • reader identifier

Exists to test one editorial hypothesis: whether the comparison surface is the thing that earns clicks, or whether the articles do.

EV-05 · reported_order

Fires when: Never automatically. It is entered by hand from an Amazon Associates Central order report for a dated period.

Records

  • report period start/end
  • ASIN (when the report itemises one)
  • reported clicking-site subtag
  • orders
  • reported revenue
  • date the report was read

Never records

  • inferred or modelled orders
  • a conversion rate computed from mismatched windows

This is the only revenue-bearing event, and it is first-party: it comes from the owner's authorised report, never from this site. A score or forecast is deliberately absent.

Privacy rules the counter must keep
  • No cookies are set by the counter. If a cookie is ever added, the footer statement and the §3(e) disclosure change in the same commit.
  • No persistent identifier per reader and no cross-site profile. Program Policies §2(b) separately forbids associating a sub-tag with a specific end user.
  • The counter records the event, the page slug and the product ASIN — never an IP address, user agent string or referrer.
  • Program Policies §3(s) forbids artificially generating clicks; the counter must never be fired by a bot, prefetch or crawler, so it is attached to a real click only.

Started empty on purpose, per the brief's 'empty but well-defined campaign ledger'. A row may only be added from an authorised first-party report. No conversion score and no revenue forecast is presented anywhere in this repository.
