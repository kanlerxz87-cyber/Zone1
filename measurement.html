Measurement: five events, one endpoint, an empty ledger

Measurement ships before the next guide is written, because a topic chosen from a number nobody can audit is the same as a topic chosen by instinct. The counter is on every page. The endpoint contract is fixed. The ledger is empty on purpose.

Status: built, not yet deployed. The client counter ships on every page and the endpoint contract below is fixed, but no endpoint is configured yet (endpoint.url is empty). Until it is filled, events are counted in the page's own memory for the current visit only and nothing leaves the browser. The site says so in plain words rather than implying measurement that does not exist. This is a deliberate, published state, not an oversight.

Rules the collector must follow

  • Reject any request carrying a cookie, an authorization header, or a field not in payload_shape.
  • Do not store the client IP address. Derive a coarse country from it in memory, then discard it.
  • Do not store a user agent string. Derive a boolean is_bot from it in memory, then discard it.
  • Store aggregates: event id, page path, coarse country, is_bot, and a UTC day bucket. Never a per-event timestamp finer than the day.
  • Rotate the daily bucket key; a retained bucket is at most 14 days old.

Client side: silent. A blocked or missing endpoint must never change what the reader sees or break a link.

Campaign ledger — empty by design

This ledger is deliberately empty. It is the record of what the campaign actually did, and at the time it was created the site had not yet served a single eligible session. An empty ledger with fixed column meanings is more useful than a filled one with invented numbers: the columns cannot be quietly redefined later to make a bad month look better.

Fill rule. Add a row only when every value in it was read from an authorized first-party report - Amazon Associates Central for orders and earnings, the site's own self-hosted collector for sessions and clicks. Never estimate a missing cell, never back-fill from memory, and never carry a number forward from a previous row. If a value was not read, leave the field empty and add a provenance note saying why.

Cookies & privacy

This site sets no cookies itself, runs no analytics, and has no comment forms or accounts. The outbound-click counter on these pages counts clicks in the browser's own memory for the current visit and sends nothing anywhere, because no endpoint is configured yet. Following an Amazon link takes you to Amazon, whose own privacy notice and cookie practices apply from that point. No data you enter here is collected, because there is nowhere to enter it.

Amazon's Program Policies §3(e) require an accurate statement of cookie and third-party technology use on Associate sites. This notice satisfies that requirement for the current build; it updates automatically the moment an analytics endpoint is configured.
