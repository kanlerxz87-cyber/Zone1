Owner workspace · measurement

Measure only what the system can verify.

Five event definitions and a reporting cadence are ready for review. Collection is deliberately disabled: the current GitHub Pages publication has no server endpoint, no verified account connection and no approved analytics privacy notice.

Prepared, not live. The source-controlled collector is a deployment reference, not a live service. This publication currently sends no analytics events. No click totals, conversions, traffic sources or revenue are claimed.

Event definitions

In the reference design, browser payloads contain only allow-listed page/product IDs or a fixed engagement bucket, and the application stores daily aggregates rather than raw event rows. The client reads no cookies, persistent IDs, referrers, query strings or destination URLs. The collector disables its own HTTP access log; host and proxy logging must also be reviewed before deployment. affiliate_report_import is an operator-only aggregate from an authorized report, not a browser event.

The client-side events, in detail

EV-01 · page_view

Fires when: One event on the first visible, non-prerendered display of an eligible publication page. DNT, Global Privacy Control and browser automation suppress collection.

Records

  • canonical page ID

Never records

  • IP address
  • user agent
  • cookies
  • persistent identifiers
  • referrer
  • query string

Application-defined aggregate event; not proof of a human visit, a unique session, a product recommendation, or a conversion.

EV-02 · outbound_click

Fires when: A trusted primary, keyboard or middle-button activation of an explicitly marked supplied product link. Counts interest, not an order; no navigation is blocked.

Records

  • canonical page ID
  • allow-listed product/link ID when available

Never records

  • full destination URL
  • link query parameters
  • Amazon account or order data

Application-defined aggregate event; not proof of a human visit, a unique session, a product recommendation, or a conversion.

EV-03 · article_engagement

Fires when: An individual published article or buying guide is visible and focused for 60 coarse one-second intervals. Background time does not advance the counter; this is engagement, not completion.

Records

  • canonical page ID
  • fixed threshold bucket

Never records

  • exact dwell time
  • scroll trace
  • session ID
  • cross-page history

Application-defined aggregate event; not proof of a human visit, a unique session, a product recommendation, or a conversion.

EV-04 · comparison_interaction

Fires when: A trusted activation of a marked product-detail link from the comparison page, not merely a table impression.

Records

  • comparison page ID
  • allow-listed product ID

Never records

  • full URL
  • query string
  • visitor identifier

Application-defined aggregate event; not proof of a human visit, a unique session, a product recommendation, or a conversion.

EV-05 · affiliate_report_import

Fires when: An authorized aggregate first-party report is explicitly imported into data/campaign-ledger.json. It is never accepted by the browser collector.

Records

  • report timestamp
  • source report
  • reported channel
  • date range
  • eligible sessions
  • clicks
  • reported orders

Never records

  • order IDs
  • customer data
  • product advertising content
  • estimated conversions or revenue

Operator-only report import. A click is not an order.

Privacy rules the counter must keep
  • No analytics cookies, persistent reader IDs, browser storage, full URLs, referrers, query strings, IP addresses or user-agent strings are sent by the client.
  • DNT and Global Privacy Control are honored; prerendered and hidden-page time is excluded. Link events require trusted primary, keyboard or middle-button activations.
  • The collector stores UTC-day aggregate counters, not raw payloads or exact event timestamps. It rejects unknown fields, unknown page/link IDs and browser order/import events.
  • Network infrastructure sees connection metadata. The collector disables its own access log; actual host/proxy logging and retention must be reviewed separately. GitHub documents security IP logging for Pages.
  • The owner decision picker is separate from analytics. It saves choices locally in this browser only and offers explicit JSON export; nothing is submitted automatically.

Why nothing is sending yet

  • GitHub Pages is a static host, not a server for POST requests. The Python aggregate collector is implemented and tested but no production host or same-origin reverse proxy has been deployed.
  • The two configuration switches remain off; changing only one fails the build. There are no measured production totals to display.
  • The footer is generated from the collection state. It distinguishes site code from GitHub hosting logs and discloses the owner decision picker’s local-only storage.
  • Orders and conversions cannot be observed by this site. Only authorized first-party reports may populate the separate campaign ledger; an absent metric remains blank, not zero.

Privacy, cookies & local-only decision storage

This site sets no cookies itself, runs no analytics, and has no public accounts, comment forms or email-signup form. The analytics client is implemented but is not loaded: no production collector is deployed. No production event counts have been measured by this site.

The owner-only decision picker stores choices in this browser’s local storage. It sends nothing automatically; choices leave the page only when explicitly copied or downloaded. Use its clear button to remove the saved choices.

Hosting is separate: GitHub states that Pages logs visitors’ IP addresses for security. Any future analytics host or proxy also needs its own logging and retention review. Following an Amazon link takes you to Amazon, where Amazon’s privacy notice and cookie practices apply.
