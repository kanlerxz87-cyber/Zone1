Owner workspace · measurement

Measure only what the system can verify.

Five event definitions and a reporting cadence are ready for review. Collection is deliberately disabled: the current GitHub Pages publication has no server endpoint, no verified account connection and no approved analytics privacy notice.

Prepared, not live. The source-controlled collector is a deployment reference, not a live service. This publication currently sends no analytics events. No click totals, conversions, traffic sources or revenue are claimed.

Event definitions

In the reference design, browser payloads contain only allow-listed page/product IDs or a fixed engagement bucket, and the application stores daily aggregates rather than raw event rows. The client reads no cookies, persistent IDs, referrers, query strings or destination URLs. The collector disables its own HTTP access log; host and proxy logging must also be reviewed before deployment. affiliate_report_import is an operator-only aggregate from an authorized report, not a browser event.

The client-side events, in detail

EV-01 · page_view

Fires when: One event when an indexable publication page first becomes visible, per page load, after explicit enablement. DNT and Global Privacy Control opt out. This is a page load, not a unique human/session count.

Records

  • canonical page ID

Never records

  • IP address
  • user agent
  • cookies
  • persistent identifiers
  • referrer
  • query string

Canonical wire format: event and page_id; target_id or the fixed 60s bucket only where defined. Counts are not unique people, eligible sessions or conversions.

EV-02 · outbound_click

Fires when: One trusted primary or middle-button activation of an explicitly marked supplied-product link. The recorded link/product ID is not an inferred ASIN or proof of the intended listing.

Records

  • canonical page ID
  • allow-listed product/link ID when available

Never records

  • full destination URL
  • link query parameters
  • Amazon account or order data

Canonical wire format: event and page_id; target_id or the fixed 60s bucket only where defined. Counts are not unique people, eligible sessions or conversions.

EV-03 · article_engagement

Fires when: One event after 60 visible-and-focused one-second intervals on a published article or buying guide. Hidden tabs do not accumulate intervals. This is coarse engagement, not proof that the article was finished.

Records

  • canonical page ID
  • fixed threshold bucket

Never records

  • exact dwell time
  • scroll trace
  • session ID
  • cross-page history

Canonical wire format: event and page_id; target_id or the fixed 60s bucket only where defined. Counts are not unique people, eligible sessions or conversions.

EV-04 · comparison_interaction

Fires when: One trusted activation of a marked product-detail link from compare.html; the target is an allow-listed product ID. Merely seeing a table does not emit this event.

Records

  • comparison page ID
  • allow-listed product ID

Never records

  • full URL
  • query string
  • visitor identifier

Canonical wire format: event and page_id; target_id or the fixed 60s bucket only where defined. Counts are not unique people, eligible sessions or conversions.

EV-05 · affiliate_report_import

Fires when: An authorized Associates Central report is imported; the corresponding aggregate is added to data/campaign-ledger.json.

Records

  • report timestamp
  • source report
  • reported channel
  • date range
  • eligible sessions
  • clicks
  • reported orders

Never records

  • order IDs
  • customer data
  • product advertising content
  • estimated conversions or revenue

Operator-only aggregate report import; the repository ledger is empty.

Privacy rules the counter must keep
  • The client reads no cookies, persistent storage, reader IDs, referrer, query string or full outbound URL. It uses fetch with credentials omitted and no-referrer policy, never a credentialed beacon.
  • Do Not Track and Global Privacy Control disable measurement. Only marked primary/middle-button product activations are counted; scripts cannot manufacture an outbound navigation.
  • The collector rejects unknown fields and non-canonical page/product IDs. It computes the UTC date on the server and stores only daily aggregate counts, not raw event rows.
  • Request transport necessarily exposes connection information to infrastructure. The application suppresses access logs, but host/proxy logs need a separate review. GitHub Pages itself documents IP logging for security.
  • EV-05 cannot be sent by a browser. Import only authorised first-party aggregates, retain provenance, and never join click counts to an inferred order or a visitor.

Why nothing is sending yet

  • GitHub Pages is static hosting, not a Python runtime. The first-party /api/analytics/events collector must run on a verified same-origin host before any production event can be accepted.
  • The browser switch and deployment gates remain false. Tests use synthetic events and isolated temporary databases; test results never enter the campaign ledger.
  • A correct application cannot control hosting-platform security logs. Deployment requires a reviewed privacy notice and host/proxy logging policy.
  • Associates order totals are available only from an authorised account report, not from a reader click. No authorised report has been imported.
