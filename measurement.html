Owner workspace · measurement

Measure only what the system can verify.

Five event definitions and a reporting cadence are ready for review. Collection is deliberately disabled: the current GitHub Pages publication has no server endpoint, no verified account connection and no approved analytics privacy notice.

Prepared, not live. The source-controlled collector is a deployment reference, not a live service. This publication currently sends no analytics events. No click totals, conversions, traffic sources or revenue are claimed.

Event definitions

In the reference design, browser payloads contain only allow-listed page/product IDs or a fixed engagement bucket, and the application stores daily aggregates rather than raw event rows. The client reads no cookies, persistent IDs, referrers, query strings or destination URLs. The collector disables its own HTTP access log; host and proxy logging must also be reviewed before deployment. affiliate_report_import is an operator-only aggregate from an authorized report, not a browser event.

What actually ships in this repository

The canonical definitions live in data/analytics-plan.json. The browser, Python collector, and the event cards below now use identical names and payloads. EV-01 to EV-04 are browser aggregates; EV-05 is an authorized report import, never a browser conversion pixel. Legacy PHP/Worker adapters return HTTP 410 instead of accepting incompatible data. Contract tests exercise the actual generated client against the collector, not just the plan.

The client-side events, in detail

EV-01 · page_view

Fires when: Once per document when a canonical reader page first becomes visible, only after explicit collection enablement and absent DNT or Global Privacy Control.

Records

  • canonical page ID

Never records

  • IP address
  • user agent
  • cookies
  • persistent identifiers
  • referrer
  • query string

Daily accepted-event counts only. Not unique people, eligible sessions, Amazon attribution or conversions.

EV-02 · outbound_click

Fires when: A trusted primary- or middle-button reader activation of a tagged, allow-listed Amazon destination; record the site product slug, never guess an ASIN or tracking ID.

Records

  • canonical page ID
  • required allow-listed product/link ID

Never records

  • full destination URL
  • link query parameters
  • Amazon account or order data

Daily accepted-event counts only. Not unique people, eligible sessions, Amazon attribution or conversions.

EV-03 · article_engagement

Fires when: A published article or buying guide remains visible and active for the 60-second coarse threshold.

Records

  • canonical page ID
  • fixed threshold bucket

Never records

  • exact dwell time
  • scroll trace
  • session ID
  • cross-page history

Daily accepted-event counts only. Not unique people, eligible sessions, Amazon attribution or conversions.

EV-04 · comparison_interaction

Fires when: A trusted activation opens an internal product-guide link from the comparison page; table visibility alone is not an interaction.

Records

  • comparison page ID
  • allow-listed product ID

Never records

  • full URL
  • query string
  • visitor identifier

Daily accepted-event counts only. Not unique people, eligible sessions, Amazon attribution or conversions.

EV-05 · affiliate_report_import

Fires when: An authorized Associates Central report is imported; the corresponding aggregate is added to data/campaign-ledger.json.

Records

  • report timestamp
  • source report
  • reported channel
  • date range
  • eligible sessions
  • clicks
  • reported orders

Never records

  • order IDs
  • customer data
  • product advertising content
  • estimated conversions or revenue

Authorized aggregate import only; never accepted by the browser collector.

Privacy rules the counter must keep
  • Only event, canonical page_id, allow-listed target_id and the fixed 60s engagement bucket are permitted, with event-specific fields. Unknown fields are rejected, not silently retained.
  • The server adds the UTC day and increments a daily aggregate. It keeps no raw event stream, exact event timestamp, IP address, user agent, URL, referrer, cookie or persistent reader ID.
  • fetch uses credentials omit and referrerPolicy no-referrer; no beacon fallback can accidentally attach cookies. Cross-origin endpoints are refused. DNT and Global Privacy Control suppress requests.
  • The collector does not prevent the receiving host from seeing connection metadata. Review host and proxy logs and the applicable privacy/retention requirements before enabling it.
  • Only trusted primary or middle-button reader activations of an allow-listed Amazon host are observed. Measurement never prevents, wraps, redirects or automatically opens a product link. Counts can still be forged at the network level; they are not certified human sessions.

Why nothing is sending yet

  • GitHub Pages is a static host; a persistent same-origin event runtime is not deployed. Local tests do not create one.
  • The runtime, privacy/retention notice, host/proxy logging policy and end-to-end production receipt have not been approved or verified.
  • A selected tracking ID is recorded, but the account and per-product enrolled-Associates destination/report checks remain unconfirmed.
  • No authorized Associates Central aggregate report has been supplied. Clicks alone cannot establish orders or revenue.

Privacy & site technologies +

This site sets no cookies itself, runs no analytics, and has no comment forms or accounts. This GitHub Pages build sends no analytics events: the proposed first-party collector is not deployed and browser collection remains disabled. Following an Amazon link takes you to Amazon, whose own privacy notice and cookie practices apply from that point. No data you enter on reader pages is collected. The owner-only decision picker stores drafts in your own browser, only when used; it does not submit them. GitHub Pages may retain connection logs for security under its own privacy policy.

Amazon's Program Policies §3(e) require an accurate statement of cookie and third-party technology use on Associate sites. This notice describes this build; it is not a legal-compliance determination and must be reviewed the moment any analytics, embeds or affiliate-network script is added. The outbound-click counter for this site is written and shipped in assets/analytics.js but is switched off, because no endpoint host has been chosen — no analytics request is sent. Hosting still entails connection metadata. The paragraph above is generated from that switch, so it cannot describe a behaviour the page does not have.
