F-07 · The three supplied product links do not identify any product critical

Every input needed for product research, pricing, review and commission analysis depends on these three links, and none of them resolves cleanly. Two findings establish the problem: each token is 9 characters where an ASIN is 10, and each direct catalog lookup returns Amazon's 'Page Not Found' page. The counter-evidence is recorded here because it matters: the fallback page each token produced was THE SAME across two independent sessions hours apart (B04G1MEwY→B0CDY277D3, B02NbDxp3→B09B7SB46R), which is not how a random shuffle behaves. So the honest position is narrower than 'these are wrong': the landing ASINs are reproducible, but they are reached through a fallback path whose own /dp/ URL for the supplied token 404s, which is consistent with an expired or re-pointed short link whose original target has been superseded. The platform therefore treats the three ASINs as a *candidate mapping to confirm*, not as an established fact, and no product attribute on this site is presented as verified.

EVIDENCE
  • Each token is 9 characters (B04G1MEwY, B02NbDxp3, B00hJ57DV); an ASIN is a combination of 10 letters and numbers.
  • https://www.amazon.com/dp/B04G1MEwY, /dp/B02NbDxp3 and /dp/B00hJ57DV each return Amazon's 'Page Not Found' error page (fetched 2026-11-13).
  • Pro: the fallback landing was identical across two sessions, so it is reproducible rather than random.
  • Con: the requested tokens' own detail pages 404, and the landing URL carries lv=shuf / plpRedirect=mhFallback, the parameters Amazon uses when it could not find the requested page.
  • Con: no Amazon page states that a 9-character token maps to any particular ASIN.

F-01 · link.amazon is not a citable affiliate link format high

The supplied host is Amazon's mobile-link service, not the Associates linking tool. The program requires the tagged Special Link format carrying the publisher's own Associates ID as a URL parameter, and disqualifies purchases reached through a link that bounces the user to Amazon via an intermediate site without an affirmative click. A platform that stored and republished 'link.amazon/...' strings would earn nothing on the traffic it drove and would be one step from a cloaking violation.

EVIDENCE
  • Special Links must use the assigned Associates ID, appearing as XXXXX-## in the URL parameter.
  • A purchase referred by a link that sends users indirectly to an Amazon Site via an intermediate site, without requiring the customer to click a link or take some other affirmative action on that intermediate site, is a disqualified purchase.
  • 'All Special Links must be accessed directly from your Site.'
SOURCES FOR MANUAL REVIEW
  • Associates Program Policies — Participation Requirements (links on your site)

Action required: Rebuild every link from the operator's own Associates ID using SiteStripe or the Associates dashboard; never republish a third-party short link. needs review

F-04 · CORRECTED — a public commission table does exist; what is unverifiable is the ASIN→category mapping high

This session first recorded F-04 as 'no public, official commission rate exists', because https://affiliate-program.amazon.com/help/operating/schedule redirects to sign-in. That conclusion was wrong and is corrected here: the Associates Program Standard Commission Income Statement is readable without a login at the help-node URL, and its Table 1 publishes fixed rates by category (Luxury Beauty 10.00% down to 0.00% for Gift Cards and similar, with 'Physical Books, Kitchen, Automotive' at 4.50% and 'All Other Categories' at 4.00%). The genuine remaining gap is narrower: Table 1 is keyed to categories, not ASINs, and air fryers are not named, so the rate that applies to a specific product cannot be derived without a category mapping Amazon does not publish. The platform therefore publishes the table and refuses to multiply it into a per-product earning figure.

EVIDENCE
  • The help node renders Table 1 to an unauthenticated request (fetched 2026-11-13); the rate rows above are quoted from that render.
  • The legacy /help/operating/schedule path still redirects to sign-in, which is how this session initially reached the wrong conclusion.
  • No line of Table 1 names 'air fryer', and no official page maps an ASIN to a Table 1 category.
SOURCES FOR MANUAL REVIEW

  • Sign-in-gated schedule path (the misleading one)

F-11 · 'Track clicks and conversions' has no lawful first-party click-attribution source medium

Amazon reports clicks and conversions in its own dashboard. A publisher may not reconstruct identity-level click tracking: associating a sub-tag or other ID with a specific end user to monitor that user's behaviour is expressly forbidden. The measurement plan therefore counts what is genuinely available — Amazon's own reports plus aggregate first-party link-click events — and does not claim per-person attribution.

EVIDENCE
  • The policy prohibits associating any sub-tag, other ID or reporting from the program with a specific end user of the site, including dynamically assigning sub-tags to users as they arrive for the purpose of monitoring their behaviour.
  • Reporting of clicks and earnings is provided through the Associates dashboard, which requires an account.
SOURCES FOR MANUAL REVIEW
  • Sub-tag restriction (Participation Requirements)
  • Operating Agreement — reporting is Amazon's disclosure to you

Action required: Decide the analytics stack and consent banner; keep sub-tags at content level (per article, per placement), never per person. needs review
