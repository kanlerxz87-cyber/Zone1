Q-01 · Product identity

Which exact manufacturer model number does each of the three supplied Amazon links point to?

Missing - discoverable

Why it matters. Three separate Chefman 6-quart dual-basket models exist with different documented temperature ranges and functions. If the wrong model is on a product page, every specification below it is a misstatement about a product the site is paid to recommend.

Answer. No answer is published here. The official sources listed below were read and do not settle it, or it cannot be settled from outside the account. The "How to find it out" line names the step that would.

What we know, and can prove

  • All three link.amazon short links resolve to the same three ASINs on every recorded fetch: B0CDY277D3, B09B7SB46R and B08DKYBTPH (7 observation rounds, 2026-11-13 to 2026-11-15).
  • The three destination pages carry the listing titles recorded in data/products.json, except the Emeril title, which changed between 2026-11-14 and 2026-11-15 (flag F38).

What is missing

The 'Model Number' row inside each listing's Product information table. Amazon publishes it on the page but not through any open interface, so it can only be read in a browser.

How to find it out

Open each of the three links, scroll to Product information, read the Model Number row. Five minutes total. Record all three strings.

Programme compliance

Q-16 · Programme compliance

May this site display Amazon prices, star ratings or review counts?

Known and sourced

Why it matters. These are the three fields a reader expects on an affiliate page and the three an Associate site usually cannot show. Getting this wrong is the fastest route to a policy breach, so the answer has to be a rule rather than a preference.

Answer. No, unless the account holds Creators API or PA API access. Program Policies section 2(b) allows a site to show prices and availability only when Amazon serves the link or the data comes from Creators API or PA API; section 6(t) allows customer reviews and star ratings only when obtained through those same APIs. This build holds neither, so every Amazon price, rating and review count on the site is left blank and flagged. The one rating that does appear is each manufacturer's own review widget on the manufacturer's own page, shown with the date it was read - that is the brand's content, not Program Content, and it is not an Amazon rating.

What we know, and can prove

  • Program Policies 2(b), read verbatim 2026-11-15: "Product prices and availability may vary from time to time. ... your Site may only show prices and availability if: (a) we serve the link in which that price and availability data are displayed, or (b) you obtain Product pricing and availability data via Creators API or PA API and you comply with the requirements regarding use of Creators API or PA API in the License."
  • Program Policies 6(t), read verbatim 2026-11-15: "You will not display or otherwise use any of our customer reviews or star ratings, in part or in whole, on your Site unless you have obtained a link to that customer review or star rating through Creators API or PA API and you comply with the requirements for Creators API and PA API described in the License."
  • The build has an executable guard for this: check_no_price_tracking() refuses to emit a price-tracking or price-alerting element, and the site carries no price or rating values at all.

What is missing

Nothing about the rule itself - it is a settled reading of the current policy text. What is missing is whether the account will ever hold the API access that would unlock the display.

How to find it out

Not applicable to the rule. If the account later obtains Creators API or PA API access, sections 2(b) and 6(t) must be re-read against that API's own licence terms before any value is displayed.

Official sources. Associates Program Policies - Participation Requirements 2(b) and 6(t) ↗

Platform and compliance

Q-18 · Platform and compliance

Can the brief's AI agent read and analyse Amazon's own product data?

Known and sourced

Why it matters. The brief's central instruction is to build an AI platform that "automates product research, identifies trending and high-converting products, analyses pricing, reviews, competition and commission potential". If that platform is designed to read Amazon listing content, the design is either unlawful under the licence or needs written approval, and the difference decides the whole architecture.

Answer. Not under the standard licence, and this project does not attempt it. IP License section 1 says Amazon "will not allow any third party to use Program Content to, directly or indirectly, develop or improve large language or multimodal models, machine learning models or related technology". Section 2(e) forbids accessing Creators API, PA API or Data Feeds "for the purpose of aggregating, analyzing, extracting, or repurposing any Product Advertising Content ... or in the direct training or fine-tuning of a machine learning and/or foundational model" without Amazon's express prior written approval. Listing titles, prices, ratings and review counts are Program Content. The automation that remains available is exactly what this repository already does: read manufacturers' own published pages, hold a verified dataset, and generate prose that may only state values present in that dataset. That is a design constraint on the platform, not an open question.

What we know, and can prove

  • IP License section 1, read verbatim 2026-11-15: "This license does not include any downloading, copying or other use of Program Content for the benefit of any third party, or any use of data mining, robots, or similar data gathering and extraction tools."
  • IP License section 1, final paragraph, read verbatim 2026-11-15: "will not allow any third party to, use Program Content to, directly or indirectly, develop or improve large language or multimodal models, machine learning models or related technology."
  • IP License section 2(e), read verbatim 2026-11-15: "You will not, without our express prior written approval, access or use Creators API, PA API or Data Feeds for the purpose of aggregating, analyzing, extracting, or repurposing any Product Advertising Content or in connection with any software or other application intended for use by persons or entities that offer products on an Amazon Site, or in the direct training or fine-tuning of a machine learning and/or foundational model."
  • The repository already runs its automation on first-party and manufacturer data only; flag F8 records the same constraint as a platform guardrail.

What is missing

Nothing in the rule. What is missing is Amazon's prior written approval, which section 2(e) names as the only route to the restricted use and which does not exist today.

How to find it out

Only Amazon can grant it. Until approval exists in writing, the constraint stands and the platform must run on manufacturer and first-party data.
