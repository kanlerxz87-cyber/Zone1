## The decision in one paragraph

The website can be published as a useful, source-linked kitchen buying publication. It
cannot yet be represented as a revenue-optimized, fully automated affiliate business.
The immediate priorities are the money path (intended listings, approved account and
one enrolled-Associates destination/report test per product) and a persistent analytics
runtime. No search, click, conversion or profit result has been established. Do not
choose a niche, forecast revenue or scale publishing on invented demand data.

## What this session changes

- A publication front page with compact shopper navigation, illustrated format cards,
  practical question-led reading, seasonal gift/sale-day coverage, and an RSS follow route.
  Existing sourced articles are reused; this session does not add a batch of new articles.
- One **Workspace** navigation group and a complete footer dashboard index. The short
  owner brief puts known answers, missing information, discovery steps and suggested paths
  in a single sourced table; the full suggestions/questions/decision registers remain intact.
- An editorial-method page: AI assistance is disclosed, no human editor or product-testing
  experience is invented, and corrections go to the public repository issue tracker.
- A visible disclosure strip **under** the masthead, repeated in the footer. Purchase CTAs
  remain gated until the intended model and enrolled-Associates link test are recorded.
- The browser counter and Python collector use the **same** event contract. Their previous
  implementations disagreed on event names, payloads, engagement and comparison triggers.
  Legacy raw-event PHP/Worker adapters are retired rather than advertised as interchangeable.
- One canonical indexable publication. Deployment staging adds `noindex,follow` and archive
  labeling to historical-build copies without modifying other sessions' archival source files.

## Measurement: what exists versus what is live

Production measurement is **not live**. GitHub Pages is a static host and cannot run
the self-hosted collector. No authorized hosting runtime or production event receipt
is available. The code and tests must not be confused with a deployment.

| ID | Event | Meaning |
|---|---|---|
| EV-01 | `page_view` | Canonical page became visible; not a unique visitor or session. |
| EV-02 | `outbound_click` | Trusted activation of an allow-listed Amazon destination, identified by the site's product slug. |
| EV-03 | `article_engagement` | One fixed 60-second visible, focused-reading threshold; not article completion. |
| EV-04 | `comparison_interaction` | A reader opens an internal product guide from the comparison page; not table visibility. |
| EV-05 | `affiliate_report_import` | Authorized first-party aggregate report import, never a browser conversion pixel. |

The first four accept only allow-listed page/product IDs and the fixed engagement
bucket. The server stores atomic UTC-day aggregate counts. No raw event stream,
reader ID, IP, user agent, referrer, cookie, full URL or query string is persisted
by the application. Host/proxy logging remains a separate review responsibility.
DNT/GPC suppress requests; requests omit credentials. Event counts are not certified
human sessions and may be forged or undercounted. The campaign ledger stays empty.
Unreported aggregate fields remain null, never guessed as zero.

Reference: [GitHub Pages hosting and security logs](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages),
[`analytics/README.md`](analytics/README.md), [`data/analytics-plan.json`](data/analytics-plan.json).

## Publishing and organic discovery

Review one buyer question each Tuesday, beginning **24 November 2026**, with at most
one guide published after source/disclosure/link gates pass. New writing is paused
until the production measurement/access gate is cleared. This is a project operating
plan, not an assertion of search volume or popularity.

Existing articles are grouped into reader-intent clusters and emitted into the sitemap
and RSS from the same article register. Verify the Search Console property and obtain
real query/page data before describing a topic as trending or selecting it for alleged
conversion potential. No search ranking, indexing or traffic result is promised.

Official basis: [Google's people-first content and accurate-authorship guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content),

2. Persistent same-origin analytics host, privacy/retention notice, host-log review and verified receipt.
3. Authorized Search Console ownership and performance reports; no verification token can be invented.
4. A real, consenting human editor/byline if personal expertise is to be claimed.
5. Rights-cleared product photography. Current imagery is labeled editorial art, not product evidence.
6. Product conflicts: Chefman 8 Qt temperature/model/weight, Emeril preset/accessory/model differences.
7. Creators API access and use-specific permissions before Amazon-data automation. The official
   [PA-API 5 deprecation notice](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/paapiv5-deprecation)
   names Creators API as the successor. No review scraping, price alerts, training on restricted
   Program Content or autonomous spending is enabled.
