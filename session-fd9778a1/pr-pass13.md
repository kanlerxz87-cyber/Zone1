## What this pass was for

Pass 13, four tasks claimed on the board (`f0dd394`): make the site read like a **shop** rather than an audit, give
the owner a real **decision desk** so a reader can pick a path and see what must be discovered first, publish the
**question-shaped guides** from registered official sources only, and **re-read line by line** every source the new
copy relies on, publishing anything irregular rather than smoothing it over.

Four commits: `f0dd394` (board claim) · `98f4e92` (T13-1) · `c914f02` (T13-3) · `a5b9345` (T13-2 + T13-4).

## T13-1 — shopfront polish and merchandising (`98f4e92`)

* The front page opens with the three machines. Each card states capacity, the **brand's own list price** with the
  policy reason no Amazon price appears beside it, a `Best for` row and a `Check first` row. The metric tiles moved
  **under** the comparison table: they describe how the project was verified, which a shopper wants after the
  decision, not before it.
* Product pages lead with the same decision block, generated by `merch_pair()` from rows already on the page —
  sourced specs and flags — so it regenerates instead of being retyped.
* Mobile: one `clamp()` type scale per heading level, a 44 px minimum hit area on interactive chrome, a
  bottom-anchored comparison bar on reader pages only (hidden on desktop, in print, and while the footer is on
  screen, per Google's page-experience guidance registered as S38), and a hint under any table genuinely wider than
  the viewport. The bar carries no purchase button — that half of SG-38 waits for a click counter.
* **No value changed.** Disclosure band, `rel="sponsored nofollow noopener"`, the tag on every `/dp/` link and both
  compliance guards stayed exactly where they were.

`suggestions.html` gained a **decision desk** panel computed at build time — queue size, rows recorded as
implemented, rows blocked on a question, path count, and two shortlists: *unanswered questions that free the most
rows* (known/answered questions are excluded, because a settled question unblocks nothing) and *highest priority with
no path recorded*. Recording a path is one click on `decision-log.html`; its export is the file the next pass reads.

`articles/chefman-vs-emeril-air-fryer.html`, `articles/questions-before-buying-a-multifunction-appliance.html`,

later re-read cannot back-date an older guide.

## T13-4 — dated re-read stamps and the irregularities this found

registered as the basis for the sticky-bar scope. No other source was re-fetched, and this PR does not claim

**New flags on `flagged.html`, published rather than patched:**

  store variant record for `RJ38-SQSS-8T`, same product, read the same day. Nothing says which is the appliance and

  published disclosure article). Rows corrected; the duplication that caused it is the open decision.
* **F85** — this pass lands in the canonical root build only; six parallel builds keep their own CSS, their own brand
  voice and their own reproducibility gates. No HTML in those directories was touched — the request is logged for
  their owners (SG-41 / Q-30).
* **F86** — the stylesheet comment names WCAG 2.2 SC 2.5.8, and no page may state that as conformance, because
  `verify.py`'s official-host allow list contains no accessibility body. Note also 44 px is *larger* than that

* **F87** — the queue's own lede asserted "Nothing on this page has been implemented" while the decision log had
  already recorded a shipped row. Repaired structurally: that sentence is now counted from the log. The same class
  turned up in evidence-link labels (`21 suggestions`, `20 questions`, `12 articles` against registers of 44, 37 and
  24) — labels are prose, and now carry no typed counts. **SG-45** proposes the general fix.
